【個別】の「可否」という語では、一回限りの許可判断しか想起されなかった。実務上は、特定の団体やグループに対して複数回にわたり方針を決めていく案件（登録が進まない団体への段階的な措置など）が存在し、これらが既存区分のどこにも収まっていなかった。「対応」であれば、許可・不許可も継続的な働きかけも同一区分で扱える。

4. 区分タグ（11区分）

決定以下11区分の固定リスト制とし、自由記述は認めない。

区分名一言定義含まれる内容使用範囲
【理念】何を信じ、どこへ向かうのかを定める理念・ビジョン・行動規範・信仰告白通常
【体制】誰が決め、誰が動くのかを定める役割定義・決裁区分・部門との指揮系統通常

【行事】単発の催しをどう回すのかを定めるキャンプ・大会・セミナー・イベント主催通常

4-1.【対応】区分の趣旨 v10変更

制度やルールを定めるのではなく、特定の相手や案件に対して個別に方針を決めるための区分である。

想定される類型

類型例
一回限りの可否判断外部講師の招聘可否、例外的な機材貸出の許可
継続的な対応方針登録が進まない団体への段階的な措置、期限設定と条件提示
条件付きの措置一定期間の状況確認を条件とした承認
例外的な取り扱い既存ルールの適用除外を認める判断

【体制】との違い

【体制】  申請ルールそのものを定める
          例：外部出演の申請は個人単位とし、事前許可は不要とする

【対応】  そのルールを個別案件にどう適用するかを決める
          例：◯◯団体の申請は、登録要件を満たすまで保留とする
一つの案件が【体制】と【対応】の両方を生むことがある。ルールを定めた決定は【体制】、その適用判断は【対応】として、それぞれ別のスレッド・別の決定として記録する。

継続案件の扱い

【対応】の案件は、一度の決定で完結せず、複数回にわたって方針が更新される場合がある。その際は次のいずれかで対応する。

状況扱い
同じ案件で方針を追加する同一スレッド内で議論し、決定のたびに台帳へ追記する
前の決定を変更する台帳で旧行を「改訂済」とし、新規行を追加する（9-4参照）
案件が完了したスレッドを【アーカイブ済】へ変更する

4-2. IT案件の扱い

決定AIを直接使わないIT案件（Teams権限、ファイル命名規則、SharePointアクセス権限など）もすべて【AI】に含める。

9-4. 撤回・改訂の手順

【改訂前】
M-202611-018 │ 有効   │ 会議は個人アカウント発行とする │ （空欄）

【改訂後】
M-202611-018 │ 改訂済 │ 会議は個人アカウント発行とする │ （空欄）
M-202611-031 │ 有効   │ 会議はチャンネル発行に変更する │ M-202611-018
  • 既存行は書き換えず、新規行を追加する。
  • 旧行の状態を「改訂済」に変更し、新規行の旧決定IDに旧行のIDを記入する。
  • 廃止する場合は状態を「廃止」とし、新規行は作らない。
【対応】区分の継続案件では、この手順を用いる場面が多くなる。方針を段階的に更新する場合、前の決定を「改訂済」とし、新しい方針を新規行として追加することで、判断の変遷が追跡できる。

9-5. 担当者・期限・優先度を持たない理由

理由内容
役割の重複回避担当者・期限・優先度はタスク台帳が保持する項目であり、決定台帳に置くと二重管理になる
更新頻度の違い決定事項は一度決まったら動かない記録。担当者・期限は進捗で変わる情報
台帳の信頼性変わらないものだけを持つことで、過去に遡ったときの信頼度が高くなる
【対応】区分で期限や条件を設定した場合は、それ自体が決定内容であるため、決定内容の文章中に明記する。列は追加しない。
例：「◯月末までに登録が完了しない場合、活動を見合わせる」
